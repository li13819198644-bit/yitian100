# 当天记录上传与每日分析

## 使用

首页或「当天学习统计」均可点击「上传今日记录」。沿用云同步账号，上传当天逐词首答、练习次数、新旧词标记、词卡上下文及语法汇总，不上传密码、邮箱、整份进度快照或其他学习日的明细。日后每次上传积累历史，分析使用截至该日最近14个自然日内已有的日报。

界面区分未上传、等待分析、后台分析中、已完成、失败可重试。重复上传相同内容复用任务；当天内容变化则生成新版本，旧任务失效。分析使用首次作答，不能把同日重复或选择题认出变成跨天回忆证据；缺失记录保持未知。

次日按设备本地日期和时区读取对应计划，自动调整建议旧词量与到期词中的关注顺序，不修改任何单词的历史成绩或到期时间。仍执行近期到期词配额、旧积压难词上限、排除词和原有复习间隔。减负模式继续暂停新词；关闭减负模式也只在连续3天自评稳定、有跨天首答且明细完整时建议最多5个新词，并尊重用户新词上限。设置可关闭自动调整。无当日适用计划时使用原排程。

这是保守、可解释的启发式规则（rules-v1），不是经过个人数据拟合的记忆模型。15／20／25个旧词及相关阈值是产品初值，需要结合实际使用评估。自评、辨认类首答、输入类首答和提示类练习单列，不宣称得到客观长期掌握率。语法目前上传汇总，原有语法排程保持独立。

配置AI后，每次分析最多对3个关注词生成助记和双语例句草稿；模型失败不阻挡学习安排。释义、词性和历史词源不由该生成接口改写。草稿必须点击「采用这张词卡」才应用到个人词卡，支持「恢复原词卡」；所有采用版本留存在云端，不覆盖公共605词及学习进度。未配置模型时仅进行规则分析，界面如实说明。

## 触发和恢复

1. 浏览器调用 `upload_daily_learning_report`，数据库同一事务保存日报、分配版本、创建持久任务。
2. 任务表触发器通过 `pg_net` 发送已提交事件到 Edge Function `analyze-daily-report`。URL与鉴权密钥存Supabase Vault。
3. 服务端核验专用密钥，通过服务角色领取任务。`FOR UPDATE SKIP LOCKED`、3分钟租约和领取令牌防止重复执行及过期结果覆盖。
4. 读取该用户最多14天日报，生成计划和可选草稿，完成时再次检查租约和当前日报版本。
5. `pg_cron` 每10分钟唤醒一次服务，包含夜间补跑。失败退避，每版最多5次自动尝试；手机可主动重试。每次定时唤醒最多处理3个任务，适用于当前个人应用规模。

上传后手机可关闭。重新打开／返回前台会读取结果；等待时每5秒查询一次，连续轮询最长2分钟，此后可主动刷新。读取结果按登录账号隔离，并缓存供当前会话离线使用。需要启动时离线仍识别账号时，应沿用现有云同步登录能力；不能联网验证登录的启动不会把其他账号缓存当作当前账号。

## 部署

网页发布和后台部署是两个步骤；仅发布网页不会自动创建后台服务。没有部署时，上传失败会明确提示，不能显示已成功分析。

推荐使用 GitHub Actions 的 **Deploy daily learning analysis** 工作流（文件 `.github/workflows/deploy-daily-analysis.yml`）：

1. 将代码合并到默认分支，按原有 Pages 流程发布手机网页。
2. 在仓库 Actions secrets 中设置 `SUPABASE_ACCESS_TOKEN`（Supabase 管理访问令牌）、`SUPABASE_DB_PASSWORD`（该项目数据库密码）。它们用于后台部署，不能放进前端 `VITE_` 配置或提交仓库。
3. 运行工作流，填写 Supabase project reference。工作流在迁移前检查该项目与网页 secret `VITE_SUPABASE_URL` 一致，不一致时停止。本机部署另须设置 `EXPECTED_SUPABASE_URL` 为同一网页 URL 配置。
4. 若启用助记草稿，另设置 `OPENAI_API_KEY` secret，勾选启用AI并填写可用模型名；不启用即可无模型费用运行规则分析。
5. 工作流执行 `supabase db push`，部署 Edge Function，并自动生成专用工作密钥，同时配置 Edge secrets 和 Vault 通知设置。随后实际调用一次受保护的分析入口检查服务。
6. 在手机登录云同步，上传一份当天报告。确认任务进入完成状态、次日建议可读；关闭页面后也应由服务器继续完成。

工作流可能生成模型调用费用；每次最多3词、最多1500输出token、模型请求20秒超时。重复上传内容不变时不会重跑已完成任务。具体费用取决于所选模型与使用次数。

若使用本机CLI，先配置同名部署环境变量，运行 `supabase link --project-ref "$SUPABASE_PROJECT_REF"`、`supabase db push`，再运行 `node scripts/deploy-daily-analysis.mjs`。脚本在系统临时目录写权限600的密钥文件，完成后删除，不把密钥写进命令参数或日志。部署轮换专用工作密钥；中途失败可重新运行，持久任务会由后续补跑处理。

## 验证范围

`npm test` 验证分析规则、输入边界、服务器鉴权、重复/过期任务、AI失败降级、手机流程和个人词卡覆盖。`npm run check:edge` 检查服务端类型，`npm run build` 检查网页构建。

`npm run test:db` 在隔离、无网络端口的 PostgreSQL 17 Docker 容器执行真实迁移核心SQL与权限测试：日报幂等、版本递增、领取互斥、租约恢复、过期结果拒绝、重试退避、RLS账号隔离、个人词卡采用和撤回。Supabase专用的 `pg_net`、Vault、cron 传输边界使用明确的测试替身；它不能替代生产环境Webhook和定时任务联调。容器退出自动清理，不连接生产数据库。

2026-10-28 本地验证：23个测试文件、169项测试通过；数据库集成测试、lint、Edge Function类型检查和生产构建通过。当前工作环境未配置生产Supabase部署凭据，因此未执行生产部署、真实Webhook、cron及模型API联调。
